# AsterMem の仕組み

世の「AI メモリ」製品の多くは、あなたの言葉をブラックボックスに放り込む。何を覚えたのか、なぜ覚えたのか、いつ取り出されるのか、あなたには分からない。AsterMem は別の道を行く。**記憶とは、まずあなたの資産であり、AI のコンテキストはその次だ。** この文書では、このフレームワークを支えるすべての設計判断を説明する。

## 1. 原文だけが唯一の真実である

すべてのメモリはプレーンな Markdown として保存される。AI が生成するもの — 要約、タグ、プロフィール — はすべて原文の**派生物**にすぎず、いつでも原文から作り直せる。

これは潔癖主義ではない。**言い換えの言い換え**という致命的な劣化経路への防御だ。要約は非可逆圧縮であり、システムが自らの要約をさらに要約し続ければ、一巡ごとに内容はあなたが実際に書いたものから遠ざかっていく — コピーのコピーを重ねるうちに文字がにじんでいくように。だから AsterMem には一つの厳格な制約がある。**結論を生成または書き換える AI 呼び出しは、必ず原文を入力として受け取らなければならない。** 中間生成物はあくまで参考にとどまる。

MD ファイルは任意のエディタで直接編集でき、インデックスは自動で同期される。データがデータベースに閉じ込められることはない — エクスポートとは、フォルダをコピーすることにすぎない。

## 2. 二層の検索: ドキュメントと段落

長い記憶素材のうち、いま手元の問いに関係するのは、たいてい一、二段落だけだ。AsterMem は各メモリを自動的に**段落（トランク）**へと分割し、それぞれに独自の要約・タグ・エンベディングを持たせる。検索時には:

- **キーワード検索**（Whoosh 全文インデックス）が正確な一致を担う: 人名、プロジェクト名、専門用語
- **セマンティック検索**（ベクトル）が曖昧な意図を担う: 「前に気をつけろと言っていたのは何だったか」
- **ハイブリッドモード**は両者を RRF（Reciprocal Rank Fusion）で統合し、クエリの特性に応じて動的に重み付けする

AI が受け取るのは、ドキュメント全体ではなく段落単位の精密な結果だ。コンテキストウィンドウは希少資源である — 的を射た 500 語は、的外れな 5,000 語に勝る。

## 3. 検索とはナビゲーションであり、一問一答ではない

すべての検索は、結果だけでなく**次の一歩の指針**も返す。表示されなかった意味的に近いメモリの ID、ヒットに含まれるタグ、展開する価値のあるドキュメント。AI は次のクエリを推測する必要がない。あなたの記憶グラフに内在するリンクをたどればよい。

これは、人が記憶素材をたどり直すやり方の模倣だ。人は最初の検索結果で立ち止まらず、「この資料が触れていたあの件」を追って先へ進んでいく。

## 4. プロフィール: 「この人は何者か」を一回の呼び出しで

セッションのたびに AI にあなたをゼロから学ばせるのは、ステートレスな対話の根本的な無駄である。AsterMem のプロフィール層は、記憶ストア全体を高密度なコンテキストへと蒸留し、エージェントは `get_profile` を一度呼ぶだけでそれを手に入れる。

プロフィールの情報源は三層に分かれる。

1. **基本情報** — 呼び名、職業、タイムゾーンといった構造化フィールド。AI があなたのメモリから自動で埋める。どこでも自由に変更でき、**一度あなたが編集したフィールドに、AI は二度と手を触れない**。変更のたびに、旧い値はバージョン履歴へアーカイブされる。
2. **自分で書く自己紹介** — あなた自身が書いた Markdown で、一字一句そのまま AI に渡される。システムのどのコードパスもこれを書き換えられない。
3. **AI の理解** — あなたのメモリから蒸留された観察で、長期的な特徴、最近の動き、トピック概観の三段に整理される。

## 5. AI が書いた一文は、すべて遡れる

AI がプロフィールに書き込む結論には、必ず参照元メモリの ID を添えなければならない。**出所をたどれない主張は、パース層で切り捨てられる** — 審査して削除するのではなく、そもそも入り口で受け入れない。

生成と検証は独立した二つの AI 呼び出しだ。まず候補となる結論を蒸留し、次に監査役が原文と突き合わせて一つずつ確認する — 「原文は本当にこの主張を裏付けているか？」。さらに毎日の回顧が既存の結論を巡回する。参照元が削除されたものには「根拠の失効」、長らく検証されていないものには「古くなっている可能性」の印が付き、すべてがあなたの裁定を待つ保留リストへ入る。**システムは黙って削除せず、黙って信じもしない。**

## 6. ドリーミング: 低頻度の深い統合

日々の蒸留はその日の増分しか見ておらず、数か月にまたがるパターンは捉えられない。AsterMem は Anthropic の研究者が提唱した「ドリーミング」（オフライン統合）の発想を借りている。記憶ストア全体を定期的に見直す — 重複を除き、統合し、矛盾を解消し、長期的なテーマを帰納する。

鍵となる設計はこれだ。**深い統合は、決して直接には反映されない。** 生成されるのは候補バージョンであり、あなたが差分（何が追加され、統合され、削除されたか）を確認したうえで、手動で採用または破棄する。統合はイベント駆動だ — 新しいコンテンツが十分に溜まった、保留中の課題が積み上がった、一括インポートが終わった — 融通のきかない cron ジョブではない。人は決まった日程で大掃除をするのではなく、散らかりに気づいたときに片づけるものだ。

深い整理には、軽量な日常の相棒もいます：**書き込み時の整頓**です。新しい記憶が届くたび、似ている既存の記憶と天秤にかけます——古くなった決定は置き換えられ、すでに記録済みの事実は二重に保存されません。整頓はアーカイブのみで、削除は決して行いません。すべての判定は理由とともに整理履歴に残り、アーカイブされた記憶はワンクリックで戻せます。迷ったときは、すべて残します。手のかからないライブラリを望むなら、ドリームの結果を自動適用にもできます——ただしすべての結論が審査を通過した場合のみ。疑わしい項目があれば、やはりあなたを待ちます。

## 7. 見える、直せる、切れる

プロフィールとは、AI によるあなたの要約である — 間違っているかもしれないし、一面的かもしれない。だからこそ、製品は三つのことを保証しなければならない。

- **常に見える** — 「エージェントに見える内容」は一字一句そのまま表示され、隠されたプロンプトは存在しない
- **常に直せる** — どの結論も残すか削除するかを選べ、どのフィールドも書き換えられる
- **常に切れる** — プロフィールはデフォルトでオフ。オフの間は AI 呼び出しが一切発生せず、コストもゼロ

信頼は約束の上には築かれない。「いつでも開いて確かめられ、ワンクリックで直せる」ことの上に築かれる。

## 8. エージェントのために

AsterMem は従来型のドキュメントツールではない。**エージェントのためのメモリバックエンド**である。

- 完全なツール API（検索、読み書き、プロフィール）。Bearer トークン認証と、読み取り / 書き込み / 破壊的操作の三段階の権限
- 同梱の Skill パッケージ。Cursor や Claude Code などのエージェントは、インストールすればすぐ使える
- `quick_match` は、時間コンテキスト + 最も関連する段落 + 次の一歩の指針を一回の呼び出しで返す。セッションの立ち上がりのために設計された
- `capture_conversation` は、エージェントが会話をまるごと預けられる：原文はそのまま保存され、長く覚えておく価値のある部分はバックグラウンドで独立した記憶に抽出され、すべて原文にリンクされる——保存はもはやエージェントの記憶力に依存しない
- 検索応答には文字数の予算と厳格な時間制限がある：ライブラリがどれだけ大きくなっても、エージェントのターンを止めない

あなたは記憶の素材を渡す。AI があなたという人を覚えている。それが AsterMem だ。
