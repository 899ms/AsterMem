# AsterMem은 어떻게 동작하나

대부분의 "AI 메모리" 제품은 당신의 말을 블랙박스에 밀어 넣습니다. 무엇을 기억했는지, 왜 기억했는지, 언제 꺼내 쓸지 알 수 없습니다. AsterMem은 다른 길을 갑니다. **기억은 먼저 당신의 자산이고, 그다음이 AI의 컨텍스트입니다.** 이 문서는 이 프레임워크의 모든 설계 결정을 설명합니다.

## 1. 원문이 유일한 진실

모든 기억은 Markdown 원문으로 저장됩니다. AI가 생성하는 모든 것 — 요약, 태그, 프로필 — 은 원문의 **파생물**이며 언제든 원문에서 다시 만들 수 있습니다.

이것은 기술적 결벽이 아니라 치명적인 열화 경로에 대한 방어입니다: **요약의 요약**. 요약은 손실 압축입니다. 시스템이 요약을 다시 요약하면 매 라운드마다 당신이 실제로 쓴 내용에서 멀어집니다 — 복사본의 복사본처럼 몇 번이면 글자가 뭉개집니다. 그래서 AsterMem에는 강제 규칙이 있습니다: **결론을 생성하거나 고쳐 쓰는 모든 AI 호출은 입력에 원문을 포함해야 합니다.** 중간 산출물은 참고용일 뿐입니다.

MD 파일은 아무 편집기로나 직접 고칠 수 있고 인덱스는 자동으로 동기화됩니다. 데이터는 데이터베이스에 갇히지 않으며, 내보내기는 폴더 복사일 뿐입니다.

## 2. 이중 검색: 문서와 단락

긴 기억 자료에서 현재 질문과 관련된 것은 보통 한두 단락뿐입니다. AsterMem은 각 기억을 **단락(Trunk)** 으로 자동 분할하고, 단락마다 요약·태그·벡터를 독립 생성합니다. 검색 시:

- **키워드 검색**(Whoosh 전문 인덱스)은 정확한 적중을 담당: 인명, 프로젝트명, 고유명사
- **의미 기반 검색**(벡터)은 모호한 의도를 담당: "지난번에 뭘 조심하라고 했더라"
- **하이브리드 모드**는 RRF(역순위 융합)로 두 결과를 병합하고 쿼리 특성에 따라 가중치를 동적 조정

AI가 받는 것은 단락 단위의 정밀한 결과이지 문서 전체가 아닙니다. 컨텍스트 윈도는 희소 자원입니다 — 정확한 500자가 빗나간 5,000자보다 낫습니다.

## 3. 검색은 내비게이션이지 문답이 아니다

모든 검색은 결과만이 아니라 **다음 단계 안내**를 함께 반환합니다: 의미상 가깝지만 표시되지 않은 기억 ID, 적중 내용의 태그, 펼쳐볼 만한 문서. AI는 다음 검색어를 막연히 추측할 필요 없이 기억 저장소의 내재적 연결을 따라 점점 접근합니다.

이것은 사람이 기억 자료를 되짚는 방식을 본뜬 것입니다. 검색 결과 첫 줄만 보고 끝내지 않고 "이 자료에서 언급한 그 일"을 따라 계속 추적하니까요.

## 4. 프로필: 한 번의 호출로 "이 사람이 누구인지"

매 세션마다 AI가 당신을 처음부터 파악하게 하는 것은 무상태 대화의 근본적인 낭비입니다. AsterMem의 프로필 레이어는 기억 저장소 전체를 고밀도 컨텍스트로 증류하고, AI는 `get_profile` 호출 한 번으로 가져갑니다.

프로필은 세 가지 출처 레이어로 나뉩니다:

1. **기본 정보** — 호칭, 직업, 시간대 같은 구조화 항목. AI가 기억을 바탕으로 자동으로 채우며, 언제든 수정할 수 있습니다. **한번 직접 고친 항목은 AI가 다시는 건드리지 않습니다.** 값이 바뀔 때마다 이전 값은 버전 기록에 보관됩니다.
2. **직접 쓰는 소개** — 당신이 쓴 Markdown이 그대로 AI에게 전달됩니다. 시스템에는 이를 수정할 수 있는 코드 경로가 없습니다.
3. **AI가 아는 것** — 기억에서 증류한 관찰로, 장기 특성 / 최근 동향 / 주제별 정리 세 단계로 나뉩니다.

## 5. AI가 쓴 모든 문장은 추적 가능

프로필에 AI가 쓰는 모든 결론은 출처 기억 ID를 명시해야 합니다. **출처를 댈 수 없는 결론은 파싱 단계에서 바로 폐기됩니다** — 검토 후 삭제가 아니라 애초에 시스템에 들어오지 못합니다.

생성과 검수는 두 번의 독립적인 AI 호출입니다. 먼저 후보 결론을 증류하고, 검수기가 원문과 대조해 "원문이 정말 이 주장을 뒷받침하는가"를 하나씩 확인합니다. 매일 회고 점검도 돌아갑니다. 출처가 삭제되면 "출처 무효", 오래 검증되지 않으면 "구식 가능성"으로 표시되어 모두 대기 목록에 올라 당신이 판정합니다. **시스템은 조용히 지우지도, 조용히 믿지도 않습니다.**

## 6. 꿈꾸기: 저빈도 심층 정리

일일 증류는 그날의 증분만 봅니다. 몇 달에 걸친 패턴은 볼 수 없습니다. AsterMem은 Anthropic 연구자들이 제안한 "꿈꾸기 메커니즘"(오프라인 통합)을 차용했습니다. 저빈도로 기억 저장소 전체를 다시 살펴 중복 제거, 병합, 모순 해소, 장기 테마 귀납을 수행합니다.

핵심 설계는 **심층 정리의 산출물이 바로 적용되지 않는다**는 것입니다. 후보 버전이 생성되고, 당신이 diff(무엇이 추가·병합·삭제됐는지)를 확인한 뒤 수동으로 활성화하거나 폐기합니다. 정리는 이벤트 기반입니다 — 새 내용이 임계치까지 쌓이거나, 대기 문제가 누적되거나, 대량 가져오기가 끝났을 때. 고정된 크론 작업이 아닙니다. 사람도 정해진 요일에 대청소하는 게 아니라 어질러진 게 보이면 치우니까요.

## 7. 보이고, 고칠 수 있고, 끌 수 있다

프로필은 AI가 당신을 요약한 것이라 부정확하거나 편향될 수 있습니다. 그래서 제품은 세 가지를 보장해야 합니다:

- **항상 보인다** — "AI에게 전달되는 내용"이 글자 그대로 표시되며 숨겨진 프롬프트가 없습니다
- **항상 고칠 수 있다** — 모든 결론은 유지하거나 삭제할 수 있고 모든 항목은 고쳐 쓸 수 있습니다
- **항상 끌 수 있다** — 프로필은 기본 꺼짐이며, 끄면 AI 호출도 비용도 전혀 발생하지 않습니다

신뢰는 약속으로 만들어지지 않습니다. "언제든 열어 볼 수 있고, 한 번에 고칠 수 있다"로 만들어집니다.

## 8. 에이전트를 위한 설계

AsterMem은 전통적인 문서 도구가 아니라 **에이전트의 기억 백엔드**입니다:

- 완전한 도구 API(검색, 읽기/쓰기, 프로필), Bearer 토큰 인증, 읽기/쓰기/파괴적 3단계 권한
- Skill 패키지 동봉: Cursor, Claude Code 등 에이전트에 설치하면 바로 사용
- `quick_match`는 시간 컨텍스트 + 가장 관련 있는 단락 + 다음 단계 안내를 한 번에 반환하며 세션 시작용으로 설계

당신은 기억 자료를 제공하고, AI는 당신이라는 사람을 기억합니다. 그것이 AsterMem입니다.
