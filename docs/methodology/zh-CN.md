# AsterMem 是怎么工作的

大多数"AI 记忆"产品把你的话塞进一个黑盒，你不知道它记了什么、为什么记、什么时候会拿出来用。AsterMem 走的是另一条路：**记忆首先是你的资产，其次才是 AI 的上下文。** 这篇文档解释这套框架背后的每一个设计决策。

## 一、原文是唯一的真相

所有记忆都以 Markdown 原文存储，AI 生成的一切——摘要、标签、画像——都只是原文的**派生物**，随时可以从原文重建。

这不是技术洁癖，而是对抗一个致命的退化路径：**转述的转述**。摘要是有损压缩，如果系统拿摘要再生成摘要，每一轮处理都会让内容离你真正写过的东西更远——就像复印件的复印件，几轮之后字就糊了。所以 AsterMem 有一条硬约束：**凡是要产出或改写结论的 AI 调用，输入必须包含原文**，中间产物只能作参考。

你可以直接用任何编辑器改 MD 文件，系统会自动同步索引。数据不锁在数据库里，导出就是复制文件夹。

## 二、双层检索：文档与段落

一份很长的记忆素材里往往只有一两段和当前问题相关。AsterMem 把每份记忆自动切分成**段落（Trunk）**，每段独立生成摘要、标签和向量。检索时：

- **关键词搜索**（Whoosh 全文索引）负责精确命中：人名、项目名、专有名词
- **语义搜索**（向量）负责模糊意图："我上次说要注意什么来着"
- **混合模式**用 RRF（倒数排名融合）合并两路结果，按查询特征动态调权

AI 拿到的是精确到段落的结果，而不是整篇文档——上下文窗口是稀缺资源，一次给对的 500 字胜过给跑题的 5000 字。

## 三、检索是导航，不是问答

每次搜索返回的不只是结果，还有**下一步指引**：语义相近但没展示的记忆 ID、命中内容的标签、值得展开的文档。AI 不需要盲猜下一个查询词，而是沿着记忆库的内在关联逐步逼近。

这模仿的是人回溯记忆素材的方式：你不会只看搜索结果第一条，你会顺着"这份素材提到的那件事"继续追索下去。

## 四、画像：一次调用拿到"这个人是谁"

每次会话都让 AI 从零开始了解你，是所有无状态对话的根本浪费。AsterMem 的画像层把整个记忆库蒸馏成高密度上下文，AI 一次 `get_profile` 调用就能拿到。

画像分三层来源：

1. **基本资料**——称呼、职业、时区这类结构化字段。AI 根据你的记忆自动填写，你随时可以改；**你改过的字段，AI 永远不再碰**。每次变更旧值都会归档进版本历史。
2. **亲手写的介绍**——你自己写的 Markdown，原封不动交给 AI，系统没有任何代码路径可以改它。
3. **AI 的了解**——从你的记忆中蒸馏出的观察，分"长期特点 / 最近动态 / 主题概览"三档。

## 五、AI 生成的每句话都可追溯

画像里 AI 写的每一条结论都必须标注来源记忆 ID，**无法溯源的结论在解析层直接丢弃**——不是审核后删除，是根本进不了系统。

生成和审校是两次独立的 AI 调用：先蒸馏出候选结论，再由审校器对照原文逐条核实"原文是否真的支持这个说法"。每天还有回溯体检，轮流复查已有结论：来源被删了标记"来源失效"，长期未验证标记"可能过时"，全部进入待处理列表由你裁决。**系统从不静默删除，也从不静默相信。**

## 六、做梦：低频的深度整理

日常蒸馏只看当天的增量，看不到跨越数月的模式。AsterMem 借鉴了 Anthropic 研究者提出的"做梦机制"（offline consolidation）：低频地把整个记忆库重新审视一遍——去重、合并、消解矛盾、归纳长期主线。

关键设计是**深度整理的产物不直接生效**。它生成一个候选版本，你看过 diff（新增了什么、合并了什么、删掉了什么）之后手动激活或丢弃。整理由事件驱动——新内容积累到阈值、待处理问题堆积、批量导入完成——而不是死板的定时任务，就像人不是每周固定大扫除，而是看到乱了才收拾。

## 七、可见、可改、可关

画像是 AI 对你的概括，可能不准、可能片面。所以它在产品上必须满足三个条件：

- **始终可见**——"AI 看到的内容"逐字展示，没有隐藏的提示词
- **始终可改**——每条结论可以保留或删除，每个字段可以改写
- **始终可关**——画像功能默认关闭，关掉后不产生任何 AI 调用和费用

信任不是靠承诺建立的，是靠"你随时可以打开看、随手可以改掉"建立的。

## 八、为 Agent 而设计

AsterMem 不是一个传统文档工具，它是一个 **Agent 的记忆后端**：

- 一套完整的工具 API（搜索、读写、画像），Bearer Token 鉴权，权限分读/写/破坏性三级
- 附带 Skill 包，Cursor / Claude Code 等 Agent 装上即用
- `quick_match` 一次调用返回时间上下文 + 最相关段落 + 下一步指引，专为会话开场设计

你提供记忆素材，AI 记住你这个人。这就是 AsterMem。
