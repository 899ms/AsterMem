# AsterMem 是怎麼運作的

大多數「AI 記憶」產品把你的話塞進一個黑盒，你不知道它記了什麼、為什麼記、什麼時候會拿出來用。AsterMem 走的是另一條路：**記憶首先是你的資產，其次才是 AI 的上下文。** 這篇文件解釋這套框架背後的每一個設計決策。

## 一、原文是唯一的真相

所有記憶都以 Markdown 原文儲存，AI 生成的一切——摘要、標籤、個人檔案——都只是原文的**衍生物**，隨時可以從原文重建。

這不是技術潔癖，而是對抗一個致命的退化路徑：**轉述的轉述**。摘要是有損壓縮，如果系統拿摘要再生成摘要，每一輪處理都會讓內容離你真正寫過的東西更遠——就像影印件的影印件，幾輪之後字就糊了。所以 AsterMem 有一條硬性約束：**凡是要產出或改寫結論的 AI 呼叫，輸入必須包含原文**，中間產物只能作參考。

你可以直接用任何編輯器改 MD 檔案，系統會自動同步索引。資料不鎖在資料庫裡，匯出就是複製資料夾。

## 二、雙層檢索：文件與段落

一份很長的記憶素材裡往往只有一兩段和當前問題相關。AsterMem 把每份記憶自動切分成**段落（Trunk）**，每段獨立生成摘要、標籤和向量。檢索時：

- **關鍵字搜尋**（Whoosh 全文索引）負責精確命中：人名、專案名、專有名詞
- **語意搜尋**（向量）負責模糊意圖：「我上次說要注意什麼來著」
- **混合模式**用 RRF（倒數排名融合）合併兩路結果，按查詢特徵動態調整權重

AI 拿到的是精確到段落的結果，而不是整篇文件——上下文視窗是稀缺資源，一次給對的 500 字勝過給跑題的 5000 字。

## 三、檢索是導航，不是問答

每次搜尋回傳的不只是結果，還有**下一步指引**：語義相近但沒展示的記憶 ID、命中內容的標籤、值得展開的文件。AI 不需要盲猜下一個查詢詞，而是沿著記憶庫的內在關聯逐步逼近。

這模仿的是人回溯記憶素材的方式：你不會只看搜尋結果第一條，你會順著「這份素材提到的那件事」繼續追索下去。

## 四、個人檔案：一次呼叫拿到「這個人是誰」

每次會話都讓 AI 從零開始了解你，是所有無狀態對話的根本浪費。AsterMem 的個人檔案層把整個記憶庫蒸餾成高密度上下文，AI 一次 `get_profile` 呼叫就能拿到。

個人檔案分三層來源：

1. **基本資料**——稱呼、職業、時區這類結構化欄位。AI 根據你的記憶自動填寫，你隨時可以改；**你改過的欄位，AI 永遠不再碰**。每次變更舊值都會歸檔進版本歷史。
2. **親手寫的介紹**——你自己寫的 Markdown，原封不動交給 AI，系統沒有任何程式路徑可以改它。
3. **AI 的了解**——從你的記憶中蒸餾出的觀察，分「長期特點 / 最近動態 / 主題概覽」三檔。

## 五、AI 生成的每句話都可追溯

個人檔案裡 AI 寫的每一條結論都必須標註來源記憶 ID，**無法溯源的結論在解析層直接丟棄**——不是審核後刪除，是根本進不了系統。

生成和查核是兩次獨立的 AI 呼叫：先蒸餾出候選結論，再由查核器對照原文逐條核實「原文是否真的支持這個說法」。每天還有回溯健檢，輪流複查已有結論：來源被刪了標記「來源失效」，長期未驗證標記「可能過時」，全部進入待處理清單由你裁決。**系統從不靜默刪除，也從不靜默相信。**

## 六、做夢：低頻的深度整理

日常蒸餾只看當天的增量，看不到跨越數月的模式。AsterMem 借鏡了 Anthropic 研究者提出的「做夢機制」（offline consolidation）：低頻地把整個記憶庫重新審視一遍——去重、合併、消解矛盾、歸納長期主線。

關鍵設計是**深度整理的產物不直接生效**。它生成一個候選版本，你看過 diff（新增了什麼、合併了什麼、刪掉了什麼）之後手動啟用或丟棄。整理由事件驅動——新內容累積到閾值、待處理問題堆積、批次匯入完成——而不是死板的排程工作，就像人不是每週固定大掃除，而是看到亂了才收拾。

## 七、可見、可改、可關

個人檔案是 AI 對你的概括，可能不準、可能片面。所以它在產品上必須滿足三個條件：

- **始終可見**——「AI 看到的內容」逐字展示，沒有隱藏的提示詞
- **始終可改**——每條結論可以保留或刪除，每個欄位可以改寫
- **始終可關**——個人檔案功能預設關閉，關掉後不產生任何 AI 呼叫和費用

信任不是靠承諾建立的，是靠「你隨時可以打開看、隨手可以改掉」建立的。

## 八、為 Agent 而設計

AsterMem 不是一個傳統文件工具，它是一個 **Agent 的記憶後端**：

- 一套完整的工具 API（搜尋、讀寫、個人檔案），Bearer Token 驗證，權限分讀/寫/破壞性三級
- 附帶 Skill 包，Cursor / Claude Code 等 Agent 裝上即用
- `quick_match` 一次呼叫回傳時間上下文 + 最相關段落 + 下一步指引，專為會話開場設計

你提供記憶素材，AI 記住你這個人。這就是 AsterMem。
